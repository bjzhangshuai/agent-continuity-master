# 控制台 UI 完整演示路线

本地入口：<http://127.0.0.1:18080/>。本次演示日期：2026-09-03。

新增「路线 C：收款 → 结算 → 本人账户提现 → 到账/退回」，见本文末尾。路线 A/B 的数量与账期是当天 19:35 的历史验收快照；资金模块验收后新增了测试记录，以页面当前数据为准。

## 开始前

- 使用上述 HTTP 地址，不要直接打开源码中的 `index.html`。
- 页面已使用本地演示账号连接。凭据仅在页面内存中；刷新整个网页后需要重新连接。普通查看数据使用栏目内的“刷新”。
- 如果侧边浏览器太窄，可拉宽浏览器面板或在浏览器大窗口中打开。消费表格在窄屏内可以左右滚动。
- 所有付款均选择“本地模拟支付（不扣款）”。微信、支付宝、PayPal、Stripe 显示待配置是预期状态。
- 原先的 UI 演示只恢复端口转发；后续资金模块已滚动更新本项目应用、添加独立表，未重启数据库或 Rancher Desktop。18080 转发单独后台运行，仅绑定 127.0.0.1。

## 路线 A：运营与跨 Agent 连续性（约 3 分钟）

### 1. 运营总览

打开“运营总览”，观察任务健康分布、Agent 实例分布、优先处理任务与业务场景。

演示初始为 53 个任务；本次增加了一条“支付全流程 UI 演示（本地模拟）”后为 54 个任务。共有 18 个演示 Agent 实例、7 台登记设备。看板的恢复成功率、负载和 SLA 等是演示数据，不代表实测的真实 Agent 运行性能。

### 2. 从风险任务下钻

在优先处理任务中点击“生产故障协同 INC-06”。查看：

- 受阻状态、紧急优先级、任务目标；
- 来源设备 `demo-operations-mac`；
- Cursor → Claude Code 的接力关系；
- 事件时间线、对话记录、产物与版本；
- 任务 DAG / 分支、参与者和审计。

“连续性”栏目展示当前选中的任务详情。未选任务时，应先从“运营总览”或“任务”选择一个任务。

### 3. 预览跨 Agent 恢复

找到“恢复预览”，将“目标 Agent”切换为 Claude Code，然后点击“预览连续性包”。

检查 JSON 中的 `target_agent: claude`、任务信息、历史事件、产物清单与分支。这里只生成/展示恢复数据，不会启动 Claude、不调用付费模型，也不等于真正执行了跨 Agent 恢复。

### 4. 查看设备与组织

打开“Agent 与工作区”：查看六种接入适配能力、18 个实例、设备名称与平台、组织和团队。例子包括“产品负责人 · iPhone”“现场支持 · Android”“客户成功 · Windows”。这些是已登记的演示身份，不表示对应设备上的 App 已在线连接。

### 5. 查看权限、开发者和市场

- “安全”：查看只读运营、自动化发布、安全审计等凭据的权限范围和审计事件；不用点击授权变更。
- “开发者”：查看企业中台、Web 工作台、移动端 App 的 OAuth 客户端示例。当前 Webhook 列表为空，不伪装已有实际外部回调。
- “市场”：查看上架模板、能力包、适配器和已安装项。当前交易列表为空；市场未与本支付模块完成真实资金结算绑定。

## 路线 B：消费 → 账单 → 支付 → 回执（约 5 分钟）

### 6. 理解用量与费用

进入“用量与计费”。先查看计费账户、套餐额度、用量汇总和逐条计量。

本次新增一条演示消费后，当前演示账户的最近 30 天窗口显示 889 条用量。列表只展示最近部分记录，正式出账按完整时间窗口聚合。默认价格仅用于演示，不是正式报价或 AI Token 成本。

### 7. 预览并生成新账单

本次已经实际演示的选择为：

- 账户：专业版 · CNY；
- 起始时间：2026-09-03 19:24；
- 结束时间：2026-09-03 19:35；
- 点击“预览消费费用”，看到 1 次 API 操作、费用 CNY 0.01；
- 点击“确认生成账单”，生成不可变的用量和价格快照。

**此时间段已经出账，不要再次生成同一账期的账单。** 重看效果可预览，或直接打开下方已有账单。重新演示出账需要新的实际演示用量和未出账的过去时间窗口；有效账期重叠会被拒绝，空用量的零金额账单无需付款。

### 8. 创建付款链接并模拟付款

打开待支付账单 → 选择“本地模拟支付（不扣款）” → “创建付费链接” → “打开安全收银台”。

核对账单号、金额、渠道 demo、环境 simulation，然后点击“模拟支付成功”。返回管理页，点击栏目内“刷新”，看到已支付、渠道流水和回执。

如果内置浏览器未打开新收银台标签页，可以复制该链接到浏览器，或直接使用管理页的“模拟付款成功/失败”按钮。付费链接含独立付款权限，应谨慎分享；它不携带工作区登录凭据。

### 9. 回执、明细、审计与查单

在已支付账单中：

1. 点击“下载消费明细 CSV”，核对数量、单价、单位、金额和价格版本。
2. 点击“下载可打印回执”，查看账单号、支付单、渠道流水、金额和支付时间。
3. 展开“支付审计轨迹”，查看出账、创建支付、等待付款和付款成功的顺序。
4. 点击“主动查单 / 对账”；已经成功的付款应保持成功，不增加重复回执。

内置浏览器在本次演示中未返回下载文件，因此已通过同一导出接口将本次文件保存到：

- 消费明细：`.data/ui-demo-ZVXahu/consumption.csv`
- 付款回执：`.data/ui-demo-ZVXahu/payment-receipt.html`

回执不是税务发票，也不是银行到账证明。模拟回执不代表真实资金到账。

### 10. 失败重试与撤销链接

- 打开 CNY 2.67 的失败样例：账单仍为“待支付”，下方保留 3 次失败支付尝试。点击“创建付费链接”可以创建新的尝试；不要删除失败记录。
- 打开 CNY 2.65 的待付款样例：可以继续模拟成功或失败，本次尚未付款。
- 对已支付的 CNY 0.01 账单，本次已点击“撤销分享链接”。旧链接 HTTP 404、管理页不再提供分享入口；已支付状态、渠道流水和回执仍保留。撤销链接不等于退款，也不取消渠道订单。

## 路线 C：收款 → 结算 → 提现 → 到账（约 5 分钟）

1. 点顶栏「收款与提现」（窄屏导航可以横向滚动），先看六步流程与模拟资金卡片。
2. 当前五个固定样例分别为：银行 CNY 1.00 已到账、支付宝 CNY 0.50 处理中、银行 CNY 0.30 失败、银行 CNY 0.10 到账后退回、支付宝 CNY 0.25 待审批。额外的 CNY 0.01/0.02 记录是实际执行的 API/UI 验收，保留完整历史。
3. 在「提现状态筛选」选择待审批，即可看 CNY 0.25 的申请、冻结金额、本人账户。点「批准提现」→「提交转出」→「模拟到账」，检查状态变化和回单入口。也可选驳回/取消，观察资金释放。
4. 在自己的账户里，银行和支付宝虚拟账户已验证；PayPal USD 账户保留待验证，用于观察验证与币种限制。不要输入真实卡号或钱包账号。
5. 可自行申请 CNY 0.01：选择已验证的 CNY 账户，输入 0.01，勾选本人确认，提交审批。没有确认、超过两位小数、余额不足、币种不匹配或未验证账户不能转出。
6. 展开「全过程审计」，能看到申请、批准、提交、渠道处理中、到账、退回的时间与操作人；「模拟到账后退回」会恢复余额但保留历史回单。
7. 点击「查看原付款账单」回到原账单、消费明细、支付流水与付款回执；旧支付模块并未替换或移除。
8. 如需从付款端开始：点「发起支付 / 查看账单」，打开原待付款 CNY 2.65 样例，用管理页「模拟付款成功」完成付款，再返回资金中心导入回执、模拟渠道结算。旧分享链接可能超过 35 分钟有效期，链接失效不代表账单删除；模拟成功按钮仅用于本地演示。
9. 下载资金 CSV 和转出回单。若内置浏览器不提供下载文件，可查看已通过同一 API 导出的 `.data/treasury-demo-FOXzXx/` 下文件。

验收完成时模拟资金为：实付 2.75、手续费 0.01、待结算 0、可提现 0.99、冻结 0.75、已转出净额 1.00（CNY）。后续交互会改变这些数字。历史退回 0.14 是累计值，不应再加到余额上。

真实资金：当前部署只启用 demo。Stripe 自有银行提现适配需独立配置与验收；微信/支付宝/PayPal 的真实提现仍在官方商户后台完成。详见 [收款与提现的能力边界及配置](treasury.zh-CN.md)。
